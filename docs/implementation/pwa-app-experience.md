## Implemented architecture

The application remains ASP.NET Core 10 SSR with InteractiveServer. `App.razor` adds manifest/theme/Apple metadata, a shared startup component and manually started Blazor. The lifecycle module starts the framework after DOMContentLoaded so all prerendered component state is available. Startup is a static shared component, so it introduces no extra persistent circuit. For existing interactive pages, the documented server circuit onCircuitOpened callback is the readiness signal; static SSR pages become ready when framework initialization completes. This preserves navigation/authentication circuit lifetimes and uses real startup signals rather than a timer. Standalone launch shows the branded Guide and “Preparing your map…” immediately after app assets load. At eight seconds it explains the longer wait; at 45 seconds or a framework startup rejection it offers explicit reload. A late successful connection removes the cover immediately. Ordinary browsers retain readable SSR content and get a compact longer-wait/error notice. Native launch screens remain browser/OS controlled; the manifest supplies theme/background/icons rather than pretending to control native artwork.

The manifest has stable id/scope/start URL `/`, name/short name DiaperScout, English language, standalone display and cream `#faf5ec` colours. It has 192/512px ordinary icons, an opaque 512px maskable icon with critical compass artwork inside the safe area, and an Apple 180px icon. No orientation restriction is imposed. `pwa/icons/source.svg` is the owned vector source, independent of manufacturer artwork.

### Caching, update and offline maintenance

`service-worker.js` precaches exactly nine owned public assets: static offline HTML/CSS/JS, brand logo, Guide WebP and four icons. It caches no application document, API, catalogue image, account, administrator, passkey, affiliate, price, stock or provider response. Non-GET, cross-origin and non-allowlisted requests pass through. Exact allowlisted static requests with query strings also pass through. Navigation goes to the network with no-store and a 20-second bounded wait; connection failures and server 5xx use the sealed offline page. No dynamic information is included in that page. An offline banner on already-open pages reminds users that current information needs a connection.

Cache name is `diaperscout-pwa-static-v1`. **When any allowlisted asset changes, increment this cache version** and preserve the prefix. Activation removes only older caches with this application prefix. Worker and manifest responses use no-cache so updates are revalidated. A new worker normally waits; a discreet update notice appears only when an existing controller is present. Update requires explicit confirmation explaining unsaved work. Only that confirmation posts ACTIVATE_UPDATE and allows this tab to reload on controller change. Dismissing suppresses the same waiting worker for the current tab; normal browser lifecycle can also activate once old tabs close. Other open tabs are not forcibly reloaded.

Installation is offered only through an explicit About-page button after a real beforeinstallprompt event. There is no automatic prompt; dismissal stores only a boolean preference. iOS instructions appear contextually on About, and installed/standalone mode hides both offers. No domain data or authentication material is stored by this module. Registration failure leaves connected browser functionality available.

### Reference and release procedure

Manual startup follows [Microsoft's Blazor startup guidance](https://learn.microsoft.com/aspnet/core/blazor/fundamentals/startup): server settings belong to the Web App `circuit` property. The circuit lifecycle hook is defined in the [.NET 10 source](https://github.com/dotnet/aspnetcore/blob/v10.0.0/src/Components/Web.JS/src/Platform/Circuits/CircuitStartOptions.ts). The prototype was [DiaperScout's live reference](https://diaperscout-prototype.pages.dev/). Browser assets are part of the Web Docker image; deploy Web only after full regression and Release verification. The previous verified Web image can be restored with the same established image-only process if needed; no schema rollback is necessary.

The next useful PWA enhancement is real-device installation and accessibility validation on iOS Safari and Android Chrome, including safe-area behavior and multi-tab update UX. Atlas and Backpack remain deferred, and no new barcode feature is proposed by this release.
