# Scan, physical observations, public submissions and Atlas

## Inspection and implementation plan

The existing domain persists Location, Observation, EvidenceItem, Country and canonical PackType. Locations currently require a Retailer even though the domain documentation allows independent places. Observations have author, timestamps, state and unused price fields, but only link Product rather than exact PackType. No public location or Atlas query exists. The existing scanner stops its camera after a successful detection and has manual entry fallback; its result screen currently offers no journey onwards. Product Details accepts variant identity but does not yet restore exact size/pack from its URL. CatalogueSubmission is a separate persisted moderation stage; creation is currently moderator-only and publication always creates a product. Sign-in currently returns to a generic landing page.

Reuse these concepts and existing authenticated identity/forwarding, catalogue projection, scanner, passkeys, PWA shell and moderation queue. Add exact PackType provenance to Observation; structured independently identifiable public-commercial Location coordinates, contributor provenance and deduplication identity; public read queries; authenticated first-party contribution services. Preserve old observation and location records without retroactively publishing them. New schema changes must be additive, apart from relaxing Location's retailer relationship to optional as the domain specifies.

Build known scan → exact product URL or authenticated observation → select/create a shop → save → success → Atlas. Extend canonical lookup to reject ambiguous mapping safely. Build unknown scan → guided public submission → authenticated final submit → existing queue. Add an editorial resolution action that can map a proposed barcode to an existing canonical pack without creating duplicate products; retain editorial authorization/audit. No generic notes field or public contributor identifiers are needed.

Atlas will show only qualifying dated observations at explicitly confirmed public commercial places. Submitted contributor evidence will be labelled as reported, never editorially verified stock or canonical facts. Locally hosted Leaflet and interactive OpenStreetMap raster tiles are appropriate for this small validation release; default browser HTTP caching and Referer are retained, visible attribution is required, and there is no tile prefetch, offline map download or geocoding service. Select the shop on a map or enter coordinates explicitly; do not infer coordinates from an address or silently publish GPS. A structured location/product list remains usable if maps fail.

Authentication remains public for discovery and required for every contribution mutation. Return URLs must remain local and allowlisted. Unknown-product work can survive the sign-in boundary as a short-lived per-tab draft containing product information only, with explicit submission and clearing afterwards; location/GPS history will not be stored in browser storage. Final writes derive identity from the authenticated principal and validate canonical relationships, prices, timestamps and explicit place semantics server-side.

Read: domain-model/entity-reference, ADR-0004 and ADR-0011, community observations/evidence, catalogue-submission-pipeline, authentication-strategy/security, public-variant-catalogue, commerce-plugin-architecture, pwa-app-experience, web-data-protection, migration/deployment/database/backup documentation and branding character guidance. Current production implementations and this request supersede older v1 exclusions of public contributions/PWA/Atlas and older scouting terminology.

Implement and inspect migrations, prove isolated persistence/security/browser workflows, run the full suite and Release build, then deploy the API/Web images and approved additive migration using the existing process. Preserve shared Web Data Protection, all network/scaling settings and API scale-to-zero. Production smoke is read-only; Simon's genuine physical observations are never test cleanup targets. Physical iPhone acceptance is explicitly pending until Simon performs it.

Map dependencies: [Leaflet reference](https://leafletjs.com/reference.html), [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/). Automated map tests must stub tile requests; do not pan headless browsers against the public tile service.

## Implemented architecture and workflows

The existing scanner now validates GS1 check digits for GTIN-8/12/13/14 and expands camera-detected UPC-E to UPC-A. Leading-zero representations resolve the same identifier. Conflicting identifiers across current packs return a safe 409 and a structured warning for editorial diagnosis, without making the contributor resolve a canonical conflict. Camera scanning stops at a result, and cannot restart until “Scan another item”. Manual input and lookup wait for the scanner's interactive handlers, preventing prerender input loss/native form submission. The native detector and locally hosted ZXing fallback remain available.

Known results show canonical identity, variant, size, quantity, packaging and GTIN. Product links include both variantId and packTypeId; Product Details restores the size owning that pack. Observation links carry the exact pack. Product display naming uses the existing public identity helper; storage names remain untouched. No imagery is fabricated or used without an existing authorized source.

`Location` remains the physical-place entity. Its Retailer relationship is now optional, matching the documented distinction between chains and branches. A contributor-created shop records structured name/address/locality/postcode/country, explicitly selected coordinates, authenticated creator, creation time, public-commercial confirmation and a deterministic normalized place identity. Duplicate input returns the existing shop and never overwrites its position. New shops are contributor-confirmed public places, not provider-verified POIs. Exact-address deduplication is deliberately modest; spelling/address differences may still require later editorial resolution.

`Observation` adds nullable PackTypeId and ContributionId. Existing author, observed/created timestamps, state and optional price fields are reused. The service derives ProductId from the pack, requires a current canonical product and confirmed public shop, validates date/price/ISO currency, and submits the dated report. UTC timestamps use PostgreSQL microsecond precision, including retry comparisons. Unique author/contribution IDs make replay idempotent; altered payloads fail validation. No notes, retailer offers or canonical metadata are written. Existing legacy observations and locations retain their meaning and do not become public retroactively.

`/observations/new` supports shop search/selection or minimal structured creation, an explicit map pin/manual coordinates, local observed time and optional shelf price. UK-first currency defaults to GBP but remains editable. No GPS permission or user-location history is collected. Save failures retain component fields; successful saves offer Atlas, product and another scan. An expired/disconnected circuit can still require sign-in/re-entry; offline mutation queues are not implemented.

`/contribute/product` is a separate public three-step journey (Product, Pack, Review), with GTIN already populated and optional version/manufacturer/size/quantity. Final submission requires authentication and creates a Source=Explorer CatalogueSubmission in InVerification, with the actor from the principal. Incomplete manufacturer knowledge uses an explicit submission-only placeholder; existing publication still requires canonical manufacturer resolution. The existing queue/editor provides corrections, evidence verification, rejection and publication. A proposed quantity is retained even when size is unknown.

Moderators can approve a verified proposal and explicitly resolve its GTIN to a current existing pack. The service checks PublishAtlas authority, Approved status, valid GTIN and conflicting identifiers; one atomic save attaches the identifier, closes the submission against that Product/Pack, and appends an editorial decision and catalogue audit. It creates no Product/Variant/Size/Pack. The parent editor refreshes after resolution, removing stale publication actions. Public photo uploads are deliberately deferred: the existing image editor is editorial, and this release does not expand untrusted file-upload permissions.

Sign-in return context is allowlisted to the two contribution routes and protected with the existing shared ASP.NET Core Data Protection keys in an HttpOnly, SameSite=Lax, 30-minute cookie. Magic links, passkeys and development sign-in consume it only on success. Public product information and the idempotency ID survive the boundary in per-tab sessionStorage for 30 minutes, then clear after confirmed submission. Coordinates/auth tokens are never stored there. Blocked storage fails visibly before navigation, keeping the draft on screen; it does not promise recovery after a reload. Authentication cancellation returns to the same journey. Parallel sign-in tabs share the last return cookie; drafts themselves remain per-tab.

All new contribution API writes use Explorer authorization and a per-principal 30/minute, zero-queue limiter. Editorial resolution uses the existing moderator permission. Identity is never accepted from DTOs. Web writes use existing authenticated API forwarding, not browser cookies as API credentials. Existing antiforgery/passkey behavior remains, and the email sign-in form explicitly renders an antiforgery token. Public read DTOs exclude authors, profile IDs, private legacy coordinates and internal notes. Commercial-place confirmations do not constitute proof that a submitted address is genuinely a shop; stronger place/evidence moderation is a future improvement.

Atlas reads Submitted/Accepted physical availability reports at explicitly public shops, joins exact current canonical packs and excludes unmatched/retired/legacy private records. The latest 2,000 reports are bounded for this first release; the selected place displays up to 50. Counts refer to distinct reported packs in that bounded set, not stock or all-time totals. Markers show shop identity, count and latest observation date; list/detail links carry exact pack context. An empty Atlas invites a genuine first observation, without invented markers. API/network failures have a user-triggered retry; tile or map-library failures leave structured lists/manual coordinate fields available.

Leaflet 1.9.4 is vendored with its license. Styles are included in the normal app stylesheet set because enhanced navigation removes dynamically inserted head styles. Browser-interactive OSM tiles use visible attribution, HTTPS, normal browser identification/Referer and default HTTP caching. No geocoding, secret/paid map keys, prefetch, offline tile downloads or automated tile crawling are introduced. `Maps:TileUrl` can switch providers without changing domain data; operators must update attribution/license requirements as part of any provider switch. OSM is best effort with no SLA and is appropriate only while usage remains within its policy; reassess before higher-volume use. Its servers receive ordinary tile request metadata. The conservative service worker is unchanged: only its existing sealed public static allowlist is cached; locations, observations, proposals, identity and prices remain network-authoritative.

## Migration and rollback

`20261001141156_PhysicalObservationsAndPublicProposals` adds nullable provenance/relationship/proposal fields, public-place false default, supporting foreign keys and null-safe unique indexes. It relaxes Location.RetailerId to nullable and replaces the single SubmittedByUserId index with a compound index retaining that leading column. Up contains no data rewrite, column/table deletion or automatic public-place conversion. Generated SQL was reviewed, and an isolated migration regression downgrades a disposable legacy fixture then reapplies Up to verify catalogue/users/listings/submissions/location/observation preservation. Down is not a production rollback strategy: it removes the new fields and cannot represent independent shops. Roll back application images while retaining this additive schema.

The existing private `ds-bootstrap-admin` Container Apps job can execute a migration-image template override without changing its persistent configuration. Copy its template, replace only image/command/args for this execution, preserve the pg-connection secret reference, resources and identity, and run the EF bundle. Clear the bootstrap-only argument; never run admin bootstrapping as part of migration. This follows [Azure's execution-template override mechanism](https://learn.microsoft.com/en-us/azure/container-apps/jobs). API/Web deployment remains image-only, retaining shared Web Data Protection, network configuration, API scale-to-zero, ingress/TLS and replica settings. No new Azure resource is required.

## Deliberately deferred and physical acceptance

No Backpack implementation, social feed, ratings, badges, routing, recommendations, inventory claims, global POI imports, automatic geocoding, GPS assistance, offline contribution queue, public photos, complete place/evidence trust system or observation editing is introduced. Price is an observed shelf fact, not a checkout/affiliate offer. Canonical barcode conflicts require editorial diagnosis. A contributor can knowingly enter a wrong public-shop location; confirmations, authenticated provenance and moderation extensibility are the current boundary.

Simon must validate the installed iPhone PWA on the real device: open → central Scan → scan a real known pack → confirm exact identity → Record where you found it → existing passkey/email sign-in if needed → select or create the actual shop → explicitly select its map position (not a home/current GPS position) → optionally enter price/currency → Save → confirm success → View in Atlas → tap marker and inspect exact product/dated report → close and relaunch → verify persistence. Check camera permission-denied/manual entry, keyboard and bottom-nav clearance. For a genuinely unknown GTIN, use Add Product → Product/Pack/Review → authenticate → submit → verify it reaches the existing moderator queue without automatic publication. Do not create dummy production observations or alter/delete Simon's real observation for acceptance.

Physical-device success is pending Simon's test. The known multi-replica SignalR transport issue and API cold-start latency are not changed or hidden by this release.
